## 改动边界

保留 apply_patch schema/example/recovery、workspace/path safety、模型 request_total/TTFT/generation/usage，以及 shell/returncode/timeout/truncation。保持一个 message-driven Agent Loop，不增加 Agent、Scheduler、后台工具任务或固定 workflow。

Progress 以事实为主：步数、最后修改、修改文件、未验证范围、validation debt、最近错误与 model-declared plan。移除 small implementation / 重复 search 等策略性催促。旧 stagnation 计数只发 telemetry，不再向模型注入策略提示。Plan completed 不代表真实 coverage/correctness。Recent errors 只包含 tool、error_code、failed_file、最多240字符detail，不复制原始 shell command；原始工具日志仍如实保存。

Validation 记录 none / partial / behavioral 和 `validation_after_last_mutation`。Mutation 重置该标记并产生 debt；后续检查（包括失败或 partial）记录“检查过”，仅可靠行为测试成功清除显式 scope 对应 debt，unknown scope 保留。Import/compile/smoke/exit0 不自动清 behavioral debt。JUnit 是可选强证据，直接 pytest/python -m pytest（可带一个 cd && 前缀）的未截断标准结果摘要也可作为证据。未识别命令、管道/复合命令、退出状态不明保持 partial，不造通用测试解析器、不改写命令、不自动运行测试。Scope 仍是模型声明而非实际测得覆盖率。

## 唯一新增行为：一次完成冲突提醒

第一次正常 final stop 且无 tool call，如果当前 run 仍有 pending/in_progress plan 或 debt=true，保留该 assistant 响应和 completion_nudge 事实事件，下一步使用 request-only reminder。模型可以继续工作、调整计划或明确说明未解决限制；不强制mutation。每 run 最多一次，JSONL恢复后仍遵守该上限。第二次final允许completed；无冲突时原语义不变。

提醒占用既有步骤，不增加 max_steps/agent timeout。如果首次冲突final恰好是末步，则限额优先，返回limited，不额外请求。提醒不是原始用户消息，不进入持久化conversation或compaction摘要；只是下一次task request的后缀，计入输入预算。模型私有协议续接仍只由adapter处理。
