# V0.3 第一阶段：真实轨迹驱动的工程优化

本轮由用户任务授权，在 `codex/nexus-v0.3-stage1` 分模块交付，不合入
`codex/nexus-v0.3` 或 main。以下变更局部替代开发设计 §6.3 的跨 Run 隔离规则，
保留单 Agent Loop、工具配对、原始日志和显式 Resume 的安全语义。

## 证据与解释边界

只读检查用户指定的五份本地 JSONL，未提交原始轨迹、私人路径或协议数据。
以下是有限样本的事实，不是总体成功率统计：

- 首次只读审计：19 steps / 28 tool calls；嵌套 PowerShell 导致变量被外层展开、
  `Select-String -Recurse` 参数不适用。只读任务本来就不应产生修改，不能把探索都算浪费。
- Click 首轮：20 steps / 19 calls，模型返回 completed 却未修改代码。
  completed 只代表模型给出终止回复，不是独立任务验收。
- FilePilot 创建：19 steps / 29 calls，后台服务清理失败结束。
- FilePilot 连续开发：40 steps / 41 calls 后 limited；显式 Resume 后
  16 steps / 15 calls 返回 completed。恢复后的 Git 调用亦有非零退出。
- FilePilot Bug 修复：27 steps / 32 calls 后模型返回 completed。
- 三份 FilePilot 日志中共 5 次缺失 Begin Patch、2 次 old block not found，
  多次将 CMD 的 `cd /d`、`dir /b` 与 Windows PowerShell 5.1 不支持的 `&&` 混用。
  这些属于可定位的工具开销；仅凭日志不能证明哪些必要探索本可省略。

## 1. Conversation Continuity

执行 Run 与对话 Session 分离：普通输入仍创建新 run_id、预算、Plan 和自动 Skill 状态。
同一 Session 的近期旧 Run 通过只读 `ConversationHistory` 投影进入模型请求，
放在稳定 system/AGENTS 后、当前 Run 前。当前 Run 内此前缀保持稳定，便于缓存。
新 Conversation 不继承；显式恢复已完成 Session 也能获得此投影。

投影包含原始需求和最新补充的有界摘录、最后可见 assistant 文本、最新执行 outcome/reason。
它不是语义摘要，不把模型声称完成升级为测试通过；缺少结束事件标记为 interrupted/unknown。
旧工具结果、工具调用参数、protocol_data、旧 Plan/Skill 实例不带入新 Run。

历史序列化预算最多约为输入预算的 20%，并受 18,000 UTF-8 bytes 总上限约束；
每 Run 最多 6,000 bytes，需求每条 1,000 bytes，最后回复 2,200 bytes。
优先保留最近 Run；超长文本保留首尾，明确标记截断和省略的 Run/请求数。
极小窗口可能不携带历史。较早决策可能丢失，应由用户明确恢复/重述或通过工具查证，
本轮不做跨 Conversation 记忆、检索或额外模型摘要。

逻辑 Run 上下文与安全压缩引用保持原样。历史投影计入实际请求的容量检查、
provider 超限 fallback 和 usage 校准，但不进入 compaction 的 seq 引用或模型摘要输入。
JSONL 仍为 schema 1；run_outcomes 从已有 run_finished 重建，不迁移、不改写旧日志。

定向测试覆盖真实 ChatModel HTTP 请求的三 Run 接续、已完成 Session 重启、
失败/中断/limited 状态、跨 Conversation 隔离、200 Run 增长上限、重复投影和原日志不变。
既有 Run 压缩、HOT observation、工具配对和 interrupted_unknown 回归一起执行。

## 2. 工具协作可靠性

`apply_patch` 接受一个狭义的 framing 修复：输入以精确文件段开头、以 End Patch
结尾且没有 Begin Patch 时，只补 Begin 行。ToolResult 的 `framing_normalized`
记录此事实。缺 End、Markdown 围栏、混合协议、重复文件、歧义匹配仍拒绝。
不修改任何源文本或匹配规则；原有路径限制、预检、并发内容检查、逐文件原子写和
partial 语义不变。原有尾随空白匹配逻辑未扩大；不承诺消除既有并发检查到写入的竞争窗口。
Add File 缺少 `+` 的反馈明确到行，old block 冲突反馈提供有界的预期文本和局部重读建议。
Tool Schema 与描述强调边界、空行和直接执行 Shell。

系统环境说明按配置的 shell 文件名提供简短 PowerShell 语义：经典 powershell.exe
不支持 `&&`/`||`，CMD 参数不适用，直接写脚本以免嵌套双引号展开变量，递归搜索的
正确组合，以及保留 native test exit code。不会自动重写 `&&` 为分号，也不更改命令
退出、超时或进程清理语义。无法靠这些说明保证模型不再写错命令。

145 项定向回归通过，包含在 Windows PowerShell 实际执行变量/递归搜索和保留退出码，
以及补丁误格式、缺结束标记、重复路径、越界、冲突、部分失败、并发与原有工具测试。
5 次缺 Begin 的历史失败支持此窄修复的选择，但尚未做固定条件下的模型对照或 Benchmark，
不能据此宣称整体成功率或平均轮次提升。

## 3. 有限预算与交接

最后 3 个模型轮次提示优先验证与如实交接，最后 1 轮明确工具结果仍会保存，但本窗口
不能再由模型检查或生成交付报告。不增加轮次、不禁止最后一轮工具、不自动执行额外摘要，
max_steps 仍是硬上限。模型正常终止仍为 completed，不能据此推断独立验收通过。

非 completed 的 run_finished 增加可选 handoff：本执行窗口的 outcome/reason、步数、
最近 5 个工具的状态/消息 seq/有限事实、未知副作用数量、最新模型 Plan 的完成项数与
最多 5 条待办。只读/命令成功不推断为代码变更，任意命令退出 0 不推断为测试通过。
verification 固定标记 runtime 未作判断；没有后续有效模型回复的工具结果明确标记。
完整工具输出和 Plan 原文仍在原始事件中；交接不能替代现场检查。

同 run 显式 Resume 时，在 request-only 状态后缀带入前一窗口交接；后续普通新 Run
只通过有界历史投影获得旧状态，不接管旧 Plan。旧日志缺少 handoff 时仍按原规则恢复。
崩溃后未知调用仍补 interrupted_unknown，不自动重放；尚未派发的同批调用保持 not_executed。
TUI 用简短中文说明未完成交付、最近工具结果、待办和显式 Resume 入口。

124 项定向测试覆盖最后一轮真实 apply_patch、run_finished 持久化、重启后实际 HTTP
续接请求、无旧工具重放、取消时 unknown 与 not_executed 区分、TUI 与原有预算/恢复/压缩。
硬崩溃或磁盘写入失败可能没有完整 handoff，仍以原始记录和未知副作用规则为准。

## 4. 中文可见进度

新增可选 `[runtime] response_language = "zh-CN"`，默认简体中文，也接受 `en` 和
`auto`（跟随用户本轮语言）。明确的用户语言请求优先。语言说明放在稳定系统前缀，
要求用可见文本简短报告下一行动与目的，保留代码/命令/路径，不翻译工具参数。
配置不热更新，开启新 Conversation 后生效。

当前 adapter 只将 `delta.content` 转为 assistant_delta；TUI 展示这些可见文本。
供应商 `reasoning_content` 保存为服务绑定的私有 protocol_data，用于必要续接，
不会作为公开进度展示。本轮不修改它、不请求公开内部推理、不添加未验证的供应商语言参数。
模型原生内部推理语言不是本方案控制或验收的对象；无需依赖供应商对此提供保证。
模型是否始终遵循中文可见输出指令仍需实际使用确认，离线测试只能确认指令与数据流正确。
不增加翻译调用；TUI 原有英文命令标签等固定布局保留，新增交接提示为中文。

建议优先审查：

1. `core/conversation.py` 与 `core/context.py`：摘录取舍、容量计入、丢失较早决策的边界，
   压缩输入和正式请求的分离；新统计为历史 bytes/estimated tokens，不表示账单或缓存命中。
2. `core/handoff.py`、`core/agent.py`、`app/session.py`：交接事实、写入失败、未知副作用与
   显式 Resume 的原 run_id；没有自动继续执行或额外模型轮次。
3. `tools/patch_format.py` 与 `tools/patch.py`：framing 规范化必须不能扩大匹配/路径权限，
   失败反馈与部分写入事实；保留现有严格度及原有并发保证的边界。
4. `app/config.py`、`core/context.py`、`app/tui.py`：可见语言与私有协议严格分离，
   稳定前缀、一次模型请求和原有 TUI 风格。

实际 Dogfooding 仍需确认：连续追问是否足够自然；长需求摘录是否丢关键约束；
模型是否按预算提醒及时验证；中文进度遵从率；Shell 失败率和重复探索是否下降。
后台常驻服务清理、Git 暂存体验及模型过早声称完成仍是后续项，本轮不增加强制完成判定器。
