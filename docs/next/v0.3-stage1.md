# V0.3 第一阶段：真实轨迹驱动的工程优化

本轮由用户任务授权，在 `codex/nexus-v0.3-stage1` 分模块交付，不合入
`codex/nexus-v0.3` 或 main。以下变更局部替代开发设计 §6.3 的跨 Run 隔离规则，
保留单 Agent Loop、工具配对、原始日志和显式 Resume 的安全语义。

## 证据与解释边界

只读检查用户指定的五份本地 JSONL，未提交原始轨迹、私人路径或协议数据。
以下是有限样本的事实，不是总体成功率统计：

- 首次只读审计：19 steps / 28 tool calls；嵌套 PowerShell 导致变量被外层展开、
  `Select-String -Recurse` 参数不适用。只读任务本来就不应产生修改，不能把探索都算浪费。
- Click 首轮：20 steps / 19 calls，模型返回 completed 却未修改代码。
  completed 只代表模型给出终止回复，不是独立任务验收。
- FilePilot 创建：19 steps / 29 calls，后台服务清理失败结束。
- FilePilot 连续开发：40 steps / 41 calls 后 limited；显式 Resume 后
  16 steps / 15 calls 返回 completed。恢复后的 Git 调用亦有非零退出。
- FilePilot Bug 修复：27 steps / 32 calls 后模型返回 completed。
- 三份 FilePilot 日志中共 5 次缺失 Begin Patch、2 次 old block not found，
  多次将 CMD 的 `cd /d`、`dir /b` 与 Windows PowerShell 5.1 不支持的 `&&` 混用。
  这些属于可定位的工具开销；仅凭日志不能证明哪些必要探索本可省略。

## 1. Conversation Continuity

执行 Run 与对话 Session 分离：普通输入仍创建新 run_id、预算、Plan 和自动 Skill 状态。
同一 Session 的近期旧 Run 通过只读 `ConversationHistory` 投影进入模型请求，
放在稳定 system/AGENTS 后、当前 Run 前。当前 Run 内此前缀保持稳定，便于缓存。
新 Conversation 不继承；显式恢复已完成 Session 也能获得此投影。

投影包含原始需求和最新补充的有界摘录、最后可见 assistant 文本、最新执行 outcome/reason。
它不是语义摘要，不把模型声称完成升级为测试通过；缺少结束事件标记为 interrupted/unknown。
旧工具结果、工具调用参数、protocol_data、旧 Plan/Skill 实例不带入新 Run。

历史序列化预算最多约为输入预算的 20%，并受 18,000 UTF-8 bytes 总上限约束；
每 Run 最多 6,000 bytes，需求每条 1,000 bytes，最后回复 2,200 bytes。
优先保留最近 Run；超长文本保留首尾，明确标记截断和省略的 Run/请求数。
极小窗口可能不携带历史。较早决策可能丢失，应由用户明确恢复/重述或通过工具查证，
本轮不做跨 Conversation 记忆、检索或额外模型摘要。

逻辑 Run 上下文与安全压缩引用保持原样。历史投影计入实际请求的容量检查、
provider 超限 fallback 和 usage 校准，但不进入 compaction 的 seq 引用或模型摘要输入。
JSONL 仍为 schema 1；run_outcomes 从已有 run_finished 重建，不迁移、不改写旧日志。

定向测试覆盖真实 ChatModel HTTP 请求的三 Run 接续、已完成 Session 重启、
失败/中断/limited 状态、跨 Conversation 隔离、200 Run 增长上限、重复投影和原日志不变。
既有 Run 压缩、HOT observation、工具配对和 interrupted_unknown 回归一起执行。
