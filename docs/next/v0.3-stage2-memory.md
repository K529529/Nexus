## M1：存储与工具

`app/memory.py` 管理 MEMORY.md、SCRATCHPAD.md、daily/YYYY-MM-DD.md 和 recovery。
Markdown 是权威源。条目使用完整 UUID 注释标记；正文可直接阅读。
读工具返回 ID 和内容 SHA-256 revision；修改和删除必须同时提供，拒绝模糊匹配、
过期版本、标记注入、路径越界、链接/junction 以及整文件覆盖。
手工编辑的无标记文本保留，不能通过 ID 工具误删；不自动迁移用户内容。

写入使用同目录临时文件、flush/fsync 和原子 replace。删除先持久化完整恢复记录，
再修改 Markdown；恢复追加原条目，保留后续写入，重复恢复无副作用，ID 冲突明确拒绝。
不声称跨文件事务、任意并发写入或断电后目录元数据持久性保证。
异步索引使用的 dirty 意图先于权威文件落盘；失效 epoch 先于更正/删除/恢复落盘。

工具：memory_write/read/search/forget/restore、scratchpad。Scratchpad 按单项 ID
添加、完成、撤销完成及可恢复清理。Search 在未连接 QMD 时准确返回 unavailable。
`[memory] enabled = false` 提供关闭入口；自定义/evaluation registry 默认不继承宿主记忆。

验证记录：首轮基线 576 passed / 10 skipped / 2 failed（Windows 进程清理）；
隔离系统临时目录、脱离 sandbox 后两项通过。M1 首轮全量 586 passed / 10 skipped /
1 failed：旧 Plan 测试固定断言只存在三个工具，已按新增六个公开工具更新。
9 项存储测试和 21 项存储/会话/模型配置定向测试通过。失败尝试保留于此。
uv 的首次刷新安装因另一个进程占用 nexus.exe 失败，验证改用已有 .venv Python；
未终止占用进程。未执行 Docker opt-in 测试。

### 真实模型路径

所有阶段在受控 FilePilot 工程情境的小型 Python 工作区运行，使用真实 Nexus Loop、
真实 Shell/Patch、真实主模型和真实 QMD。它们是可重复的工程夹具，**不是 FilePilot
生产仓库修改，也不是 Benchmark 总体收益结论**。每个阶段由新的 Python 进程运行。
原始公开事件及报告位于 `evidence/memory-stage2/agent-*`；私有 Session 原文保存在
本机隔离系统临时目录，不提交模型协议私有字段。所有失败尝试都保留。

主模型配置为 DeepSeek 官方 `deepseek-flash`、high、128000 context，单次 output8192、
max_steps12；独立压缩模型为 SiliconFlow `Qwen/Qwen3.5-35B-A3B`、output4096、
`enable_thinking=false`。这是请求配置身份；当前适配器没有保存 provider 返回的 model 字段。
On/Off 使用同一 TASK 提示、初始工程文件、模型及执行预算，差别为是否启用 Memory。
没有声称不同轮次的服务端随机性、缓存状态完全一致。

### 数据流与模块职责

```text
主模型 tool call → tools/memory.py 参数/分页边界
  → app/memory.py → Recovery(删除时) → dirty/epoch → Markdown 原子落盘
  → 返回操作回执；app/memory_index.py 后台合并 update → CPU embed
  → 私有 MCP 长连接 query → QMD expansion / BM25 / vector / RRF / rerank
  → 当前 Markdown docid 核对 → memory_search 回执

新 Session → app/memory_context.py 选择来源 → core/memory_snapshot.py tokenizer 截取
  → Session JSONL memory_snapshot → system 稳定末尾 → Stage1 Context Budget
  → Resume 回放原快照；普通 append 保持；epoch 变化受控刷新
```

`app/bootstrap.py` 负责组装和关闭资源，`app/session.py` 回放快照；原 Agent Loop、
Semantic Summary/Runtime Facts 与通用 MCP 继续使用 Stage1 路径。没有新编排层。

### 能力分级与边界

**已实现并有验证**：六工具及确定性修改、Markdown 持久化/恢复、真实 QMD 混合精排、
跨 Session 模型写入和使用、稳定快照预算、普通多 Run/手动及自动压缩回归、关闭与故障降级。

**已实现但未充分验证**：长期使用中的记忆质量/冲突率，大规模文档检索质量与延迟、
跨项目全局记忆的干扰、Linux QMD 安装与资源行为、任意 provider 自主记忆表现。
主模型自己写的事实仍需验证，系统不提供语义真实性保证或提示注入绝对防护。

**尚未实现**：自动 QMD 安装器、后台失败自动重试/退避、记忆去重/过期清理策略、
跨进程并发写事务和历史日志中的隐私擦除。失败后下次变更或重启会重新尝试索引。
QMD 派生库可重建，清理 `.retrieval` 后重新启动；保留 Markdown 和 Recovery。
CPU embed 避免显存争用，但冷启动及更新延迟较高；索引失败不阻塞普通编码。
手工改 Markdown 后当前 Session 保持原快照，下一新 Session 才纳入；需即时失效时用更正工具。
无标记手工文本只读保留；超长单项/无标记正文有明确截断，需要本地查看完整文件。

**有意不实现**：Project Memory、多 Agent、LangGraph、每轮自动召回、退出/定时自动总结、
自动提炼、额外 PostgreSQL/pgvector、HTTP 常驻搜索服务。

### 可重复入口

先按使用手册安装 QMD；使用源码环境中已有依赖和真实配置/API 环境变量。
验收脚本不会修改全局配置，主模型和压缩模型仍从 `~/.nexus/config.toml` 读取。

```powershell
$env:PYTHONPATH = 'src;.'
$qmdEntry = "$env:LOCALAPPDATA/Nexus/qmd/node_modules/@tobilu/qmd/dist/cli/qmd.js"
# 每次实验使用新的专用目录；Output 必须不存在，保留所有物理尝试。
python scripts/memory_qmd_smoke.py --home <fresh-memory-dir> --qmd-entry $qmdEntry --output <new-output>
python scripts/memory_agent_acceptance.py --phase remember --home <isolated-home> --workspace <workspace-a> --qmd-entry $qmdEntry --output <new-output>
python scripts/memory_agent_acceptance.py --phase autonomous --home <same-home> --workspace <fresh-workspace-a2> --qmd-entry $qmdEntry --output <new-output>
python scripts/memory_agent_acceptance.py --phase task --home <same-home> --workspace <fresh-workspace-b-on> --qmd-entry $qmdEntry --output <new-output>
python scripts/memory_agent_acceptance.py --phase task --off --home <same-home> --workspace <fresh-workspace-b-off> --qmd-entry $qmdEntry --output <new-output>
```

`query` / `maintain` / `compact` / `resume` / `offline --qmd-missing` 为其余阶段。
`--resume <session.jsonl>` 必须使用原工作目录。共享一个 home 的阶段顺序运行，
避免把未设计的多进程并发索引引入本轮验收。阶段报告 `EXECUTED` 只表示 Run 完成；
任务成功要看独立 verifier、工具回执及具体验收断言。

下一轮建议固定任务/知识集与 On/Off 预算，记录任务正确率、错误记忆使用率、
新知识保存召回率、检索 Top-k/精排收益、输入/输出及缓存 tokens、模型费用、
首答/完成时间、索引滞后、CPU/显存、Snapshot 命中与前缀稳定性。
