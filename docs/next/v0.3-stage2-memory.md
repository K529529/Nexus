## M1：存储与工具

`app/memory.py` 管理 MEMORY.md、SCRATCHPAD.md、daily/YYYY-MM-DD.md 和 recovery。
Markdown 是权威源。条目使用完整 UUID 注释标记；正文可直接阅读。
读工具返回 ID 和内容 SHA-256 revision；修改和删除必须同时提供，拒绝模糊匹配、
过期版本、标记注入、路径越界、链接/junction 以及整文件覆盖。
手工编辑的无标记文本保留，不能通过 ID 工具误删；不自动迁移用户内容。

写入使用同目录临时文件、flush/fsync 和原子 replace。删除先持久化完整恢复记录，
再修改 Markdown；恢复追加原条目，保留后续写入，重复恢复无副作用，ID 冲突明确拒绝。
不声称跨文件事务、任意并发写入或断电后目录元数据持久性保证。
异步索引使用的 dirty 意图先于权威文件落盘；失效 epoch 先于更正/删除/恢复落盘。

工具：memory_write/read/search/forget/restore、scratchpad。Scratchpad 按单项 ID
添加、完成、撤销完成及可恢复清理。Search 在未连接 QMD 时准确返回 unavailable。
`[memory] enabled = false` 提供关闭入口；自定义/evaluation registry 默认不继承宿主记忆。

验证记录：首轮基线 576 passed / 10 skipped / 2 failed（Windows 进程清理）；
隔离系统临时目录、脱离 sandbox 后两项通过。M1 首轮全量 586 passed / 10 skipped /
1 failed：旧 Plan 测试固定断言只存在三个工具，已按新增六个公开工具更新。
9 项存储测试和 21 项存储/会话/模型配置定向测试通过。失败尝试保留于此。
uv 的首次刷新安装因另一个进程占用 nexus.exe 失败，验证改用已有 .venv Python；
未终止占用进程。未执行 Docker opt-in 测试。

## M2：QMD 检索与最终一致性

M1 已提交推送 `b5579cd28f1b26484de0eedb89160491a3c852e8`，远端 SHA 一致。
M1 修复旧断言后 63 项定向测试、全量 Ruff/Mypy 通过。

实际安装 QMD 2.8.3（Node 22.23.2），Embedding 为 Qwen3-Embedding-0.6B Q8_0，
Reranker 为 QMD 默认 Qwen3-Reranker-0.6B Q8_0，Expansion 为默认 qmd-query-expansion-1.7B Q4_K_M。
GGUF 存在 QMD 用户缓存，仓库不包含模型或派生数据库。
`app/memory_index.py` 使用独立配置/SQLite、固定 collection mask 和显式 index 参数，
防止工作目录的 `.qmd` 配置接管。一个后台任务拥有一个可复用 MCP stdio client；
主模型只看见 memory_search，通用 MCP 注册路径保持原样。

所有变更统一写 dirty 意图，0.3 秒合并，后台 `qmd update → qmd embed`。
启动对比内容指纹及上次状态，补齐中断更新。状态写入 `.index.json` 和 Session 事件；
失败不清 dirty，搜索拒绝 pending/failed/unavailable，普通工具继续使用。
搜索还核对返回文档的 QMD content docid 与现有 Markdown，剔除不再匹配的命中。
恢复记录不进入 collection。查询采用 QMD 原生自动 expansion、混合检索和 rerank。

真实验收脚本 `scripts/memory_qmd_smoke.py` 使用新建隔离目录，不读取真实私人记忆。
全部尝试见 `evidence/memory-stage2/qmd-attempt-*`：

- attempt-1 FAIL：错误拒绝 QMD 自动写入的 models 配置，已修复。
- attempt-2 FAIL：3 次真实 MCP 召回正确，但并发启动 CLI explain 与 MCP 争用显存而崩溃。
- attempt-3 FAIL：最后条目删除后文件为空，QMD 跳过空文件却继续返回旧内容。
- attempt-4 PASS（86.67s）：三个查询首条命中正确；中文召回英文工程记录；同一 MCP
  连接跨写入、删除、恢复保持复用；删除结果不再含 sentinel，恢复后再次可检索。
  `needsEmbedding=0`、`hasVectorIndex=true`。独立 CLI explain 的真实回执包含
  ftsScores、vectorScores、RRF contributions 和 rerankScore，证明完整链路实际执行。

针对实测问题：无其他正文的最后条目删除会移除空 Markdown，让 QMD 撤下该文档；
后台 embed 使用 CPU，避免与保留 GPU 模型的 MCP 同时分配显存。CLI explain 在 MCP
关闭后独立执行。性能与模型效果只代表该五条工程材料的小样本，不代表整体任务提升。
25 项存储/索引/预算/会话定向测试通过；Ruff/Mypy 通过，Mock 与真实验收分别记录。

配置示例：

```toml

enabled = true
# 默认 ["qmd"]；Windows 推荐直连 Node CLI，避免批处理 shim/额外进程。

```

本机安装路径为 `%LOCALAPPDATA%/Nexus/qmd`，不会自动改写正在使用的用户配置。

## M3：Stable Memory Snapshot

M2 已提交推送 `c9aebfe23e893e688a73c44144f0425c19d23034`，远端 SHA 一致。
`app/memory_context.py` 选择未完成 Scratchpad、Today Daily、MEMORY.md、Yesterday Daily；
`core/memory_snapshot.py` 使用现有模型 TokenEstimator 和真实 tokenizer 分别限制
2048 / 2048 / 4096 / 1024 tokens，总额含标签、格式和参考数据说明不超过 10240。
Daily 保留最新，长期记忆保留首尾。所有内容进入 system 稳定前缀末尾，自动计入
Context 的整体估算、安全输入容量、压缩预留和 provider usage 校准。

Snapshot 在初次 Run 前构建，单独追加 `memory_snapshot` JSONL 事件；普通 append
不会更新。Resume 回放已保存正文，Compaction 不接收、不总结该区段。旧 Session
原本没有 Snapshot，恢复时保留其缺席语义。当前项目/environment 指令仍按 Stage 1
刷新，Memory 文件的普通变化不会触发该比较路径重写系统前缀。
更正、删除、恢复和 Scratchpad 状态变更通过持久化 epoch 使旧快照失效，在下一模型
请求前受控刷新；跨进程 Resume 同样检查。保留原始历史作为审计，不声称删除历史日志。
快照显式标为低优先级历史参考数据，不能覆盖用户、项目规则或安全限制。

验证：9 项 Snapshot/会话定向测试通过，覆盖两种真实 tokenizer 及 fallback、多个 Run、
新 Session、进程生命周期重建、删除/恢复后的下一模型请求、两次 Compaction、
Run 内自动 Compaction、旧 Session 和 Memory Off。语义模型使用 scripted fixture，
此处证明运行时语义，不作为真实模型记忆收益。全量回归 **599 passed / 10 skipped**
（41.84s），Ruff/Mypy 全量通过；输出保存在 `evidence/memory-stage2/m3-pytest.txt`。
