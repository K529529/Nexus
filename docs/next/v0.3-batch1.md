## 工具与证据

- apply_patch 保持既有 Nexus/legacy unified 两种解析路径、严格路径与匹配边界。增加最小合法示例与结构化 recovery 建议，不自动重试/修复补丁。
- exec_command 新增可选 purpose（inspect/validate/mutate/other）、mutation_scope / validation_scope（明确 workspace-relative 文件，最多100项）和 validation_report（本次命令生成的 JUnit XML 路径，相对 workdir 或绝对路径）。旧调用仍可执行，未声明 purpose 为 other/unspecified。
- 对声明的文件执行前后哈希，记录 shell 实际修改；不会扫描整个仓库、解析任意 shell 以猜副作用或推测完整修改范围。未声明的 shell 修改可能无法发现；声明 mutate 但范围未知时保留 unknown debt。
- validate 的 exit=0、print、import/compile 仅提供 partial/command_succeeded 证据。清除 scope 对应 behavioral debt 还要求：可识别的直接 pytest / python -m pytest 命令（不含 shell 复合操作），以及与命令参数一致、新生成且格式完整的 JUnit 报告、计数与 testcase 一致、至少一个通过用例、无失败/error、工具正常结束且验证期间 scope 文件未改动。旧报告、纯 skipped、截断 XML、缺 scope、失败/超时/取消均不能清除对应 debt。
- JUnit 提供实际报告用例计数；没有可解析报告时 tests=null。scope 是模型显式声明，不冒充测得的代码覆盖率、测试质量证明或独立官方 verdict。报告本身不是防伪安全边界。未知 mutation 范围不能靠一次局部测试清零。
- shell 保留原始 stdout/stderr、shell、exit_code（另提供 returncode）、timeout/cancel/truncation；不改写命令，不试图解析多命令的每条退出状态。

## Progress 与恢复

账本来自原始 tool messages，可在同 run resume 后重建；不依赖被投影/压缩的工具 preview。记录 mutation step/window、有界 changed/pending files、最近5个失败操作、最后验证事实；现有 Plan 展示模块覆盖情况，完成状态始终标为模型声明。请求末尾与现有 Plan/执行预算一起投影，包含动态工具清单，加入真实输入预算且不进入原始消息/safety snapshot。progress_snapshot 为可观测事件。

每次 mutation 重置对应文件 debt；有效局部验证只清除其声明 scope。最后修改后 debt 持续提醒，模型可说明未验证范围后正常结束。没有第 N 步必须修改或固定阶段。旧恢复日志缺失 step 时保留 null，窗口重新计步不用于判断验证先后。

## 模型计时

每个 attempt 保留 duration_ms/usage，并记录 request_total_ms、ttft_ms、generation_ms。TTFT 是从请求开始到首次非空正文/推理/工具载荷的客户端时间；generation 是该载荷到 finish chunk 的间隔，包含网络/服务端因素，不能视为纯解码时间。未观察到首载荷或 finish 时为 null；失败/取消保留已报告 usage，未知不补零。私有 reasoning 不进入公开事件。
