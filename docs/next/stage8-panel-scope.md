`codex/nexus-v0.3-stage8-multi-agent`。本轮处理当前任务与会话历史混排、缺少任务名称、

## 行为

- 默认面板和 `/agents` 展示当前根任务的代理树。当前任务的已完成代理仍保留，便于
  查看本轮成果；下一轮根任务开始后，已完成且没有待办的旧代理进入 `/agents history`。
  新任务没有子代理时明确显示空状态，不继续展示上一轮已完成树。
- 跨轮仍在运行、等待决策、取消/清理中、失败、受限、恢复异常、有未投递结果、
  已接收待处理指导或未确认工具副作用的代理留在默认视图，关联祖先也保留。
  跨轮节点标记 `[跨轮]`，待交付结果标记“待交付”，未知副作用标记 `unresolved`。
- 实时面板每个节点压缩为一行“任务名 · 角色 短 ID · 状态”。运行中的分支优先展示，
  旧失败不会排在本轮执行者前面。终端高度仍受限；超出时保留 `/agents` 展开提示，
  完整 `/agents` 输出不裁剪节点。历史归档不会删除代理、日志或 ID 查询入口。
- `/agents` 与 `/agents history` 同时提供任务名、角色、ID、状态、操作、耗时、
  Fresh 标记和该代理累计用量。`/agent detail ID`、选择目标和取消入口保留。
- `spawn_agent` 增加兼容性的可选 `task_name` 字段，并在工具说明/委派提示中要求提供
  用户语言的简短名称。遗漏时优先提取任务文本中的“目标 / 任务 / Goal / Task”等字段，
  再退回首个非空行；按终端单元限制到 24 格。先脱敏，再截断，避免泄漏截断的密钥前缀。
- 顶部用量明确为“会话累计（主+全部子代理）”，包括历史任务、嵌套代理和恢复前用量，
  不是本轮用量。详情的“该代理累计”包括该代理历史执行与恢复。缺少报告继续使用
  `≥N tok?`，不把未知用量当成零，不新增价格估算。

## 任务归属与恢复

`task_run_id` 记录所属根任务的 run ID，与即时父代理的 `source_run_id` 分开。
子/孙代理继承根任务归属；同一任务内收尾指导沿用 run ID，不产生新分组。
显式恢复代理时归属当前发起任务，保留代理身份、任务名和历史。

旧日志缺少新字段时，沿父链推导根任务并固定归属；名称从原任务生成。
恢复后的默认视图根据父代理已提交的 message/tool result 重建交付事实，
不会把早期 receipt 当成结果已交付，也不会重复交付已提交结果。未知副作用按既有
子代理 run ID 关联，completed 状态本身不能解除副作用风险或让它自动归档。
本轮不改变 Agent Loop、角色、额度、共享工作区、执行恢复策略或外部遥测范围。
