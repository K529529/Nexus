## 增量一：输入交接与命令健壮性（问题 1、3）

- prompt_toolkit 的同步 accept handler 保存已提交文本、Enter/Tab 模式及目标代理。
  已提交交付由独立短期 Task 持有；暂停监听只取消读输入，不取消交付。
  审批不等待提交回调完成，避免异步回调阻塞审批；任务收尾等待本次提交交接，
  再检查待处理指导，不等待下一次输入。提交成功后清除交接状态，不重复投递。
- 未提交草稿仍独立保存，原有 Enter 指导 / Tab 排队、多行、粘贴和取消行为保留。
- Inbox 接收的日志写入与内存加入作为受取消保护的一次接收事务；收到取消时先完成
  事务再传播取消。写入失败仍抛出错误，不伪造接收成功或吞掉内部异常。
- `/withdraw` 与 `/edit` 按分词检查 ID、替换文本及参数数量。缺参数、未知或已投递
  消息给出提示，输入监听继续工作。
- 新回归使用真实 prompt_toolkit 管道和异步屏障，稳定覆盖 Enter/审批、Tab/结束、
  异步回调、提交目标改变、一次交付、持久化后取消、命令错误后指导/排队及正常编辑/撤回。
  现有审批草稿、粘贴、取消和已投递不可编辑断言保留。
